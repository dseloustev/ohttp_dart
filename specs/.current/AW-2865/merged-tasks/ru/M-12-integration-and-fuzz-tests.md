# Добавить интеграционный тест с заглушкой гейтвея и fuzz/property-based тесты

**Оценка:** 2d
**Приоритет:** P2: High
**Компонент:** App
**Severity:** HIGH

## Описание задачи

В тест-suite два структурных пробела покрытия, которые усиливают друг друга:

1. Все три существующих тест-файла проверяют отдельные слои в изоляции. Нет end-to-end теста `OhttpClient.send()` против заглушки, эмулирующей GET/POST поверхность гейтвея. Регрессия, ломающая оркестрацию (сборка URL, проброс заголовков, обработка content-type, кэширование KeyConfig, таймауты), не будет поймана существующими юнит-тестами. Для библиотеки, ценность которой — корректность относительно внешней стороны, минимальное покрытие — это интеграционный тест против заглушки гейтвея.
2. Существующие тесты покрывают RFC-векторы и небольшой набор вручную подобранных негативных кейсов, но нет property-based или fuzz-покрытия varint-кодека, BHTTP-парсера или KeyConfig-парсера. Патологические входы, собранные атакующим, — ровно та поверхность, для которой fuzz-тестирование и создано. Свойства вроде «varint encode → decode — это identity» и «любой ввод в `parseResponse` либо парсится успешно, либо бросает `FormatException`» сейчас не проверяются в масштабе.

Оба пункта создают директорию и harness, которые будущие тесты смогут расширять.

## Технические детали

**1. Интеграционный тест против заглушки гейтвея** (новая директория `test/integration/`)

Директории `test/integration/` сейчас не существует. Создать её и добавить как минимум один тест, который связывает `OhttpClient` с локальной in-process заглушкой. Два подхода приемлемы; выбрать один и зафиксировать выбор в `test/integration/README.md`:

(a) **Локальный shelf-сервер**: поднять сервер `package:shelf` внутри теста, отвечающий по настроенному `configPath` синтетическим KeyConfig и по `requestPath` синтетическим OHTTP-ответом. Прогоняет весь HTTP-транспортный путь. Требует добавить `shelf` в `dev_dependencies`.

(b) **Записанная HTTP-фикстура, воспроизводимая через мок `http.Client`**: избегает реального сетевого listener'а, но всё равно прогоняет оркестрацию в `send()`. Ниже стоимость настройки; ниже покрытие реального транспорта.

Любой подход должен сохранять CI герметичным (без реальных сетевых вызовов). Тест прогоняет `OhttpClient.send()` end-to-end и проверяет путь оркестрации: discovery KeyConfig, сериализация BHTTP, encapsulation OHTTP, POST на гейтвей, decapsulation, парсинг BHTTP-ответа.

**2. Fuzz / property-based тесты**

Ввести property-based или fuzz-слой. Два практичных варианта:

(a) Использовать Dart-совместимый пакет, например `glados` (добавляет `dev_dependency`).
(b) Самописные рандомизированные генераторы с фиксированным seed на CI.

Добавить как минимум три property-теста:

- **Round-trip identity varint** по случайным значениям в `[0, 2^62)`. Для каждого сгенерированного значения `decodeVarint(encodeVarint(v))` должен равняться `v`, а закодированная форма должна совпадать с ожидаемой длиной для диапазона значения.
- **`parseResponse(randomBytes)` никогда не бросает ничего, кроме `FormatException`** (согласовано с усилением парсера BHTTP, которое заменяет `RangeError` на `FormatException`).
- **`OhttpKeyConfig.parse(randomBytes)` никогда не бросает ничего, кроме типизированных библиотечных исключений** (согласовано с типизированной иерархией исключений и фиксом парсинга нескольких suite).

Seed на CI фиксирован для воспроизводимости; механизм переопределения seed для периодических глубоких прогонов должен быть задокументирован. Один тест не должен занимать больше нескольких секунд на CI-прогоне; ограничивать количество итераций соответственно.

Любой новый тип исключения, обнаруженный fuzz-входами, должен быть триажирован: либо исправлен, либо добавлен в задокументированную поверхность исключений.

## AC

- Директория `test/integration/` существует, в ней как минимум один тест-файл и `README.md`, документирующий выбранный подход к заглушке.
- Интеграционный тест прогоняет `OhttpClient.send()` end-to-end против заглушки гейтвея, покрывая discovery KeyConfig → сериализация BHTTP → encap OHTTP → POST на гейтвей → decap → парсинг BHTTP.
- CI прогоняет интеграционный тест без доступа к внешней сети.
- Добавлены как минимум три property/fuzz-теста: round-trip identity varint, инвариант `parseResponse` на random-bytes, инвариант `OhttpKeyConfig.parse` на random-bytes.
- CI-конфигурация использует фиксированный seed для воспроизводимости; механизм переопределения seed для глубоких прогонов задокументирован.
- Один тест не занимает больше нескольких секунд на CI-прогоне.
- Любые новые типы исключений, обнаруженные fuzz-входами, либо задокументированы в соответствующих doc-комментариях, либо — если неожиданны — исправлены.
