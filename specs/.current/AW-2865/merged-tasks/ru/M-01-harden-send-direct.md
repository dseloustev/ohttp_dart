# Устранить обход OHTTP в `sendDirect` и обновить пример

**Оценка:** 2d
**Приоритет:** P1: Critical
**Компонент:** App
**Severity:** BLOCKER

## Описание задачи

Сейчас, если `OhttpGatewayConfig` сконструирован только с обязательными параметрами (необязательный `directBaseUrl` опущен), последующий вызов `sendDirect()` отправляет открытый HTTP-запрос напрямую на хост релея — без шифрования, без unlinkability, без какого-либо сигнала о том, что OHTTP-поток обойдён. Тихий fallback `directBaseUrl ?? gatewayBaseUrl` в `lib/src/ohttp_client.dart:52` превращает «вспомогательный для сравнения» метод в скрытый источник утечек приватности.

Для некастодиального крипто-кошелька это разница между нелинкуемым RPC-вызовом и утечкой активности кошелька в открытом виде оператору релея. Опасность усугубляется публичным геттером `effectiveDirectBaseUrl` на той же строке, который выставляет то же разрешение `null → gatewayBaseUrl` как вызываемую, документированную часть публичного API. Файл примера `example/ohttp_dart_example.dart` ни о чём из этого не предупреждает — ничто в примере не сигнализирует о том, что `sendDirect()` по умолчанию небезопасен.

## Технические детали

В рамках задачи выполняются три связанных изменения:

**1. `sendDirect()` больше не обходит OHTTP молча** (`lib/src/ohttp_client.dart:147-171`)

Сейчас у метода единственная строка doc-комментария («Send a direct HTTP request (for comparison).»), нет `@Deprecated`, нет `assert`, нет предупреждения о приватности. Тело метода на строках 148–171 вызывает `_httpClient.send()` против `effectiveDirectBaseUrl`, который при `directBaseUrl == null` разрешается в `gatewayBaseUrl`.

Требуется:
- Метод должен падать сразу (assert или библиотечное исключение), если `directBaseUrl` равен `null` или совпадает с `gatewayBaseUrl` — открытый трафик на релей не должен уходить молча ни при каких условиях.
- Добавить `@Deprecated('...')` с указанием влияния на приватность.
- Doc-комментарий должен явно сообщать, что вызов `sendDirect()` полностью обходит OHTTP-пайплайн — нет HPKE-шифрования внутреннего запроса, нет посредничества релея, нет unlinkability — и перечислять гарантии RFC 9458 §1, от которых отказывается вызывающий код (конфиденциальность внутреннего запроса от оператора релея, unlinkability между идентичностью клиента и содержимым запроса, изоляция метаданных от того, как целевой сервер видит клиента). Этот пункт описывает только документацию метода-обхода; приведение самого пайплайна `send()` в соответствие с RFC 9458 выполняется в других задачах.

**2. Скрыть или удалить публичный геттер `effectiveDirectBaseUrl`** (`lib/src/ohttp_client.dart:52`)

Сейчас этот геттер — публичная поверхность, через которую обнаруживается тихий fallback. Переименовать в `_effectiveDirectBaseUrl` (private для библиотеки) или перенести логику разрешения внутрь тела `sendDirect()` (строка 154), чтобы публичная поверхность вообще не упоминала fallback по имени. Обновить doc-комментарий конструктора так, чтобы он больше не описывал fallback как публичное понятие.

**3. Переработать файл примера** (`example/ohttp_dart_example.dart`)

- В основном потоке использовать только `send()`.
- Если `sendDirect()` всё-таки показан, закрыть его громким комментарием «не использовать в production — обходит OHTTP» и требовать явный `directBaseUrl`, отличный от `gatewayBaseUrl`.
- Добавить doc-комментарии для каждого поля `OhttpGatewayConfig`, особенно для `targetAuthority` (приватный backend-хост, который встраивается во внутренний BHTTP-конверт).
- Перечислить исключения, которые ожидаются для обработки.
- Сослаться на RFC 9458 §1 для гарантий unlinkability, на которые опирается пример.

## AC

- Вызов `sendDirect()` без явно указанного `directBaseUrl`, отличного от `gatewayBaseUrl`, падает сразу (assert или библиотечное исключение) и никогда не отправляет открытый трафик на релей.
- Doc-комментарий `sendDirect()` называет влияние на приватность (нет шифрования, нет unlinkability) и ссылается на гарантии RFC 9458 §1, которые обходятся.
- На методе присутствует `@Deprecated` (или эквивалентный compile-time сигнал).
- `effectiveDirectBaseUrl` больше не входит в публичный API `OhttpGatewayConfig`; внутренние места вызова продолжают работать.
- Doc-комментарий `OhttpGatewayConfig` больше не описывает fallback-путь как публичное понятие.
- В `main()` примера используется только `send()`; любое упоминание `sendDirect()` сопровождается явным предупреждением и требует отдельного `directBaseUrl`.
- Doc-комментарии в примере перечисляют все поля `OhttpGatewayConfig` и ожидаемую поверхность исключений.
- Юнит-тест воспроизводит конфигурацию с тихим fallback и проверяет, что вызов отклоняется.
