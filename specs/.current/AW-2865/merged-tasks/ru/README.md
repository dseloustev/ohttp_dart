# AW-2865: объединённые follow-up задачи (русская версия)

## Связь с `../../tasks/`

Per-task файлы в `../../tasks/` остаются источником истины для отдельных находок (ссылки на файл/строку, severity, vector). Файлы здесь — упаковочный слой для инженерного планирования: каждый можно скопировать в Jira-тикет с минимальной правкой.

Если объединённая задача отбрасывается или разбивается при планировании — вернуться к `../../tasks/` за неslit'ой версией каждой составной находки.

## Предлагаемый порядок прихода

1. **M-01** должна приходить первой — она закрывает единственный BLOCKER (обход приватности в `sendDirect`).
2. **M-05** (типизированная иерархия исключений) должна прийти до задач, вводящих новые throw-места (**M-04**, **M-06**, **M-07**, **M-12**), чтобы новые throw сразу использовали типизированную поверхность.
3. **M-07** (усиление парсера BHTTP) должна прийти до **M-10** (покрытие тестами BHTTP), так как несколько тестов из M-10 проверяют `FormatException`, который появляется только после M-07.
4. Остальные задачи в основном независимы и могут идти параллельно.
