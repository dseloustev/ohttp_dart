# Валидация схемы `gatewayBaseUrl` и `targetAuthority` в `OhttpGatewayConfig`

**Оценка:** 1d
**Приоритет:** P2: High
**Компонент:** App
**Severity:** HIGH

## Описание задачи

`OhttpGatewayConfig` принимает `gatewayBaseUrl` (внешний URL релея/гейтвея) и `targetAuthority` (приватный backend-хост, встраиваемый во внутренний BHTTP-конверт) как обычные `String` без валидации. Библиотека молча принимает `http://`-URL — хотя RFC 9458 §1 требует TLS на внешнем канале — и тогда внешний OHTTP-шифротекст передаётся открытым текстом, что даёт пассивному наблюдателю на пути возможность корреляции по таймингу относительно гейтвея и подрывает свойство unlinkability, ради которого вообще существует OHTTP. Аналогично, `targetAuthority` принимает любую строку, поэтому некорректное значение (`"https://host"`, пробелы по краям, встроенный путь) молча формирует некорректный внутренний BHTTP-запрос.

Разработчик кошелька с опечаткой в конфиге или с неправильно настроенным staging-URL не получает никакого сигнала о том, что развёртывание сломано, до момента, когда сетевой наблюдатель уже захватывает трафик или гейтвей уже возвращает ошибку парсинга внутреннего запроса.

## Технические детали

Две связанные валидации добавляются в момент конструирования `OhttpGatewayConfig` (`lib/src/ohttp_client.dart:43-51`):

**1. Принудительная схема HTTPS**

Конструктор (строки 43–50) и места, где из этих полей строятся URI (строка 82 для GET KeyConfig, строка 116 для POST на гейтвей), сейчас принимают любую схему. Отклонять любой базовый URL, схема которого не `https://`, как для `gatewayBaseUrl`, так и для `directBaseUrl` (если задан). Бросать библиотечное исключение в момент конструирования. В doc-комментарии конструктора зафиксировать обоснование (RFC 9458 §1).

Если для тестов нужен escape hatch, закрыть его явным именованным флагом (например, `allowInsecureScheme: false` по умолчанию), чтобы production-код не проходил через него случайно.

**2. Проверка формы `targetAuthority`** (`lib/src/ohttp_client.dart:97-104`)

`targetAuthority` встраивается дословно во внутренний BHTTP-запрос на `bhttp.serializeRequest(...)` (строки 97–104). Допустимая форма — это продакшн `authority` из RFC 3986: `host` или `host:port`. Отклонять:
- пустые значения,
- значения с префиксом схемы (`http://`, `https://` и т. п.),
- значения с пробельными символами,
- значения с символами пути или запроса (`/`, `?`, `#`),
- значения с символами фрагмента.

Бросать библиотечное исключение в момент конструирования. В doc-комментарии конструктора зафиксировать ожидаемую форму со ссылкой на RFC 3986 §3.2.

## AC

- Конструирование `OhttpGatewayConfig` с `http://` (или любой другой не-`https://`) `gatewayBaseUrl` бросает библиотечное исключение в момент конструирования.
- Та же проверка схемы отклоняет `http://` `directBaseUrl`, если он указан.
- Конструирование `OhttpGatewayConfig` с некорректным `targetAuthority` (пустой, с префиксом схемы, с пробелами, с путём) бросает библиотечное исключение в момент конструирования.
- Doc-комментарий конструктора ссылается на RFC 9458 §1 для требования схемы и на RFC 3986 §3.2 для формы authority.
- Юнит-тесты для схемы покрывают: валидный `https://`, отклонённый `http://`, отклонённый `ftp://`, отклонённую пустую строку.
- Юнит-тесты для authority покрывают: валидный `host`, валидный `host:port`, отклонённое пустое значение, отклонённое значение с префиксом схемы, отклонённое значение с пробелами, отклонённое значение с путём.
